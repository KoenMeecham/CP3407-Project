## Assumptions:
- Users must be logged in to save restaurants
- Restaurant data already exists in the system (from search/list pages)
- Save functionality can initially use a simple database table (no advanced caching required)
- UI can use a basic icon (e.g. heart/bookmark) without final branding
- Saved restaurants do not require sorting/filtering in MVP
- Persistence will be handled via the database (not session-only)


## Tasks
Tasks:  
Task 1 – Create wireframe for Save (Favourite) feature, Estimated 0.25 days  
Task 2 – Design database model for saved restaurants (User ↔ Restaurant relationship), Estimated 0.25 days  
Task 3 – Implement backend logic to save/unsave a restaurant (Django views/API), Estimated 0.25 days  
Task 4 – Add Save/Favourite button to restaurant UI (icon toggle), Estimated 0.25 days
