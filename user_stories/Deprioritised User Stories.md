## Deprioritised User Stories

The following user stories were identified as valuable features but were deprioritised to ensure that core ordering functionality was delivered within the iteration timeframe.

---

### Customer Experience Enhancements

1. **Repeat Last Order**  
As a customer, I want to repeat my last order with one tap.  
Reason: Convenience feature, not essential for core ordering flow.

2. **Promo Codes**  
As a customer, I want to apply promo codes for discounts.  
Reason: Not sure how to add based on the software

3. **Scheduled Orders**  
As a customer, I want to schedule an order for later.  
Reason: Not enough time

4. **Save Delivery Addresses**  
As a customer, I want to save multiple delivery addresses.  
Reason: Not enough time

5. **Restaurant Communication**  
As a customer, I want to communicate with restaurants and drivers.  
Reason: Cant do without real drivers/restaurants

6. **Personalised Restaurant Suggestions**  
As a customer, I want recommendations based on past orders.  
Reason: Requires data tracking and recommendation algorithms.

7. **Reward System**  
As a customer, I want to earn rewards and discounts.  
Reason: Loyalty systems were considered outside MVP scope.

8. **Rate and Review Restaurants & Drivers**  
As a customer, I want to leave reviews and ratings.  
Reason: Social feature, not essential for ordering functionality.

---

### Delivery Driver Features (Out of Scope)

9. **Delivery Driver Features (General)**  
As a driver, I want to register and accept delivery jobs.  
Reason: Additional user role and workflow not required for MVP.

10. **Accept Delivery Orders**  
As a delivery driver, I want to accept delivery requests.  
Reason: Dependent on full driver system implementation.

11. **Driver Earnings Summary**  
As a driver, I want to view my earnings history.  
Reason: Requires financial tracking system beyond project scope.

---

### Restaurant-Side Features

12. **Restaurant Menu Management**  
As a restaurant owner, I want to manage menu items.  
Reason: Static menu data was sufficient for MVP.

13. **Restaurant Availability Status**  
As a restaurant, I want to mark my store as open or closed.  
Reason: Coudn't implement dure to time constraints

14. **Out-of-Stock Items**  
As a restaurant, I want to mark items as unavailable.  
Reason: Mock restaurants provide no way for us to know whats out of stock

15. **Order Queue View**  
As a restaurant, I want to see incoming orders in a queue.  
Reason: Restaurant end not really client

---

### Admin / System Features

16. **Admin Order Oversight**  
As an admin, I want to view all active orders.  
Reason: Admin-level monitoring not required for MVP.

17. **Manage Users**  
As an admin, I want to manage customer, restaurant, and driver accounts.  
Reason: Adds complexity and was not essential for initial release.

18. **Fraud/Abuse Flagging**  
As an admin, I want to flag suspicious accounts.  
Reason: Security enhancement beyond project scope.

19. **System Maintenance Mode**  
As an admin, I want to disable ordering during maintenance.  
Reason: Operational feature not critical for demonstration.

20. **Performance Monitoring**  
As an admin, I want to monitor uptime and system errors.  
Reason: Advanced system feature not required for MVP.

21. **View Basic Analytics**  
As an admin, I want to view usage analytics.  
Reason: Data insights were not required for core system functionality.

---

### Summary

These features were deprioritised to ensure the successful delivery of core system functionality, focusing on the primary user journey of browsing restaurants, placing orders, and tracking deliveries. These features may be implemented in future iterations to enhance usability, scalability, and overall system performance.
